# uc-server-db

Оригинальная проектная инструкция. Применять только в рамках разрешённой задачи.

1. Прочитай карточку, архитектуру, контракт API и модель данных по её ссылкам. Сначала проверь существующие версии и миграции.
2. Применяй модульный монолит, HTTPS-команды и серверную авторизацию. Godot high-level RPC/ENet не считать готовым протоколом Go-сервера; использовать HTTPRequest и при необходимости обычный WebSocketPeer.
3. Валидация владельца и роли — серверная, для каждого объекта. Тестовый admin intent — отдельная команда с причиной и аудитом. Не доверяй цене, времени и результату производства клиента.
4. Транзакции короткие, порядок блокировок устойчивый, повтор на serialization/deadlock ограничен. Задания и исходящие события устойчивы к рестарту и повтору.
5. Миграции нумерованы и неизменяемы после публикации; тест fresh DB и upgrade. Используй expand/contract для несовместимых изменений; не обещай безопасный down для утраты данных.
6. Добавь негативные API/DB тесты, параллельные сделки и проверку отзыва прав/сессии. WS-уведомление отправляй только после commit, из сохранённого outbox.
7. Новые параметры доступны через специализированную админскую форму с аудитом; API-документ обновляется вместе с изменением.

Выход: проверенные серверные изменения без дублирования экономики на клиенте. Источники: Go, PostgreSQL, Godot networking в ai/sources.md.
