# uc-testing-security

Оригинальная проектная инструкция. Применять только в рамках разрешённой задачи.

1. Прочитай критерии задачи и выбери проверки по риску. Не подменяй реальную PostgreSQL моками там, где важны блокировки/транзакции.
2. Деньги/запасы: отрицательные значения, переполнение, нехватка, последний остаток в двух потоках, повтор ключа, изменённое тело, частичное падение, rollback и инварианты.
3. Права: чужой company_id, неактивная сессия, истёкший VIP, обычный игрок против admin route, CSRF, rate limit и недопустимая загрузка. Секреты и токены не попадают в лог.
4. Время: повтор расчёта, рестарт между фазами, доставка/порча, пропуск интервала, reconnect со старым курсором. Проверяй сохранённый результат, не просто HTTP 200.
5. Browser QA — для админки; Android install/run/UI — для APK. Сборка и статический анализ не доказывают работоспособность устройства или экономический баланс.
6. Приводи команды, exit code, версии, среду и артефакты. Не запускай случайный установочный скрипт или исполняемый helper до чтения исходника и зависимостей.
7. Недоступный ресурс → точный blocker, какие проверки выполнены, какие нет, и статус BLOCKED/REVIEW. Не создавай условно успешный CI для отсутствующего компонента.

Выход: воспроизводимые проверки и честный вывод. OWASP используется как справочник, не как автоматический сертификат.
