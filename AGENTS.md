# Правила работы с UFACAPITAL

Общение и документы — по-русски. Утверждена A — «Деловая республика». До отдельного разрешения после этапа 3: только проектные документы, никаких игрового кода, workflow-заглушек, развёртывания и генерации ресурсов. Актуальное разрешение и активная задача — в PROJECT_CONTEXT.md и ROAD.md.

## Начало задачи

1. Прочитай этот файл, PROJECT_CONTEXT.md и ROAD.md. Найди активную карточку в roadmap/tasks; затем только её минимальные документы и нужные исходники. Не читай весь проект.
2. Проверь текущую ветку, git status, последние коммиты и актуальность origin/main. Исследуй существующую реализацию до правок.
3. Выбери подходящие проектные скиллы из ai/skill-catalog.md. Codex: .agents/skills; Claude: CLAUDE.md/.claude/skills; Grok: ai/grok. Нет автоматического обнаружения — прочитай текст явно.
4. Коротко изложи план и границы изменений. Независимые AI-задачи используют отдельные ветки/worktrees; не запускай субагентов без явного разрешения применимых инструкций или заказчика.

## Реализация и проверка

- Сервер — единственный источник денег, ресурсов, времени и прав. Финансовые операции атомарны/идемпотентны, суммы целочисленные. ИИ используют те же команды, обозначены как ИИ, имеют память и собственные бюджеты. LLM не входит в экономический цикл.
- Новая настраиваемая механика получает API, админку, аудит и тесты одновременно. Все графические элементы имеют ID, происхождение, промпт и управляемую замену/версию.
- Не меняй утверждённые продуктовые ограничения без согласования. Обратимые инженерные детали можно уточнять с фиксацией последствий. Не создавай пустые каталоги или универсальные конструкторы заранее.
- Точные версии, лицензии и зависимости проверяй перед установкой. Не запускай непроверенные скрипты. Секреты, keystore, токены и реальные персональные данные — вне Git и отчётов.
- Выполни проверки карточки, проверь реальное поведение. Не выдумывай результат SDK/VPS/Android/CI. Нет обязательного теста — нет DONE; используй BLOCKED либо REVIEW и укажи причину.

## Завершение и взаимодействие агентов

- Не уничтожай и не перезаписывай чужие изменения. Запрещены force push, reset/clean с потерей работы и изменение опубликованной миграции вместо новой. При конфликте — отдельная ветка/PR и совместимость API.
- Не брать задачу, уже занятую другим владельцем. Запиши task ID/ветку/base SHA/область/время в roadmap/WORKLOG.md перед работой. Только одна активная задача в ROAD; параллельные явно перечисляются с разными владельцами и файлами.
- После реализации запусти тесты, проверь diff/секреты; обнови карточку, ROAD, PROJECT_CONTEXT. Решения заказчика записывай полностью в docs/decisions/DECISIONS.md; изменение решения — новая запись со ссылкой, без переписывания истории.
- Коммит/публикация допустимы в рамках задания. Перед push проверь свежий head; не перезаписывай чужой. Для конфликтующих задач — PR. После этапа проверь GitHub и сообщи SHA.
- Отчёт: что изменено, зачем, фактические проверки, ограничения и следующий разрешённый шаг. При передаче контекста оставь минимальную сводку в WORKLOG; большие логи/снимки — в артефактах, не в корневом контексте.
