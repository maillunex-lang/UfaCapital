# Веб-админка и управление ассетами

React+TypeScript+Vite build, same-origin HTTPS API на Go, статические файлы через Nginx. Начать с login+RBAC+списков и специализированных форм; админка развивается в той же задаче, что механика, а F07 проверяет полноту и asset lifecycle.

## Состояние на 12.11.2026

Собрана первая версия в `web/admin` (React 19, TypeScript, Vite). До появления Nginx и HTTPS её раздаёт сам Go-сервер по `/admin/`, только для 127.0.0.1.

| Раздел | Что умеет | Чего нет |
|---|---|---|
| Вход | пароль + TOTP, выход | смена пароля, перевыпуск TOTP |
| Игроки | список, роли (только суперадмин, не себе), выдача VIP с причиной | поиск, блокировка, отзыв сессий, отзыв VIP |
| Компании | список с деньгами и резервом | предприятия, штат, проводки |
| ИИ | список, пауза и снятие с причиной | память, кандидаты решений |
| Настройки | текущие значения, изменение с проверкой версии | расписание `effective_at`, история версий |
| Журнал | последние 200 действий: кто, что, причина, было/стало | фильтры, постраничный просмотр |

Не начаты: редактор рецептов/товаров/городов (API `POST /admin/api/v1/recipes` есть, формы нет), каталог и замена графики, финансы, рынок, события, синхронизация. В настоящем браузере человеком не проверялось; автотесты покрывают API, а не экран.

## Механика → обязательное управление

| Механика | Админская поверхность | Аудит/проверка |
|---|---|---|
| Аккаунты/сессии | поиск игроков, блокировка/отзыв, роли | actor/reason, запрет повышения своих прав |
| VIP/test-admin | выдача/отзыв/срок, тестовые операции | entitlement history, grants через ledger |
| Города/товары/рецепты | CRUD/deactivate, versions/effective_at | ссылки сохраняются, конфликт версий |
| Компании/предприятия | владелец, состояние, линии/штат/расходы | нет скрытого balance edit |
| Финансы/кредит | проводки/резервы/долги/фонды | компенсация отдельной операцией |
| Производство/склады | jobs, партии, простои, порча, вместимость | trace operation→inputs/outputs |
| Рынок/контракты/логистика | заявки/сделки/резервы/маршруты | допустимая отмена, нет переписи сделки |
| Население/внешний сектор | бюджет/потребность/цены/лимиты | эмиссия и transfer отчёт раздельно |
| ИИ | список, профиль, память, кандидаты/решение, pause | изменения по версии, обязательства не исчезают |
| События/коэффициенты | редактор, предпросмотр, расписание/отмена | active interval, effect version |
| Графика | все ресурсы/промпты/upload/publish/rollback | content hashes, лицензии, автор замены |
| Синхронизация | lag/jobs/outbox/ошибки | повторы безопасны, нет произвольной SQL-кнопки |

Новые механики F11/F12 добавляют собственные строки/формы одновременно с реализацией. Отсутствующая форма/аудит — незавершённая задача, не долг «на потом».

## Каталог графических элементов

Запись: asset_id, semantic type, usage targets, locale, prompt (непустой), provenance, license/status, current version, MIME, width/height, bytes/hash, runtime_policy, previous_versions. Даже ручная и временная графика содержит описание для генерации аналога. Каталог охватывает все authored images клиента/админки: UI backgrounds, иконки, товары, городские маркеры, здания, VIP-декор, launcher/splash. Текст/Control-layout не считаются графическим файлом; внешние системные glyphs не обещаются редактируемыми, встроенные шрифты учитываются отдельно.

Все используемые authored images должны резолвиться по стабильному ID; проверка полноты находит ссылку без каталога и неиспользуемую запись. Runtime замена PNG/WebP: upload→проверка сигнатуры/декодирования/лимита, например≤8MB и≤4096²pixel как исходные лимиты→preview→создание immutable version→атомарная публикация manifest(version,hash)→обновление кэша клиента→rollback на прежний manifest. SVG/HTML/script uploads не допускаются в срезе. Нельзя исполнять EXIF/встроенный код или принимать только заявленный MIME.

Новый manifest проверяется полностью до активации; при недоступности/несовпадении хеша клиент использует последний проверенный cache и сообщает ошибку. Launcher/splash/шрифты или импортируемый нестандартный ресурс имеют requires_apk: замена создаёт pending build и применяется подписанным обновлением. Админка честно показывает способ доставки изменения; «замена всех ресурсов» не означает обещание Android менять launcher без APK.

Промпт хранится, но кнопка генерации не обязательна: этот этап и первые задачи не запускают производство ресурсов без разрешения. Пользовательская замена проверяется лицензией/происхождением; чужие защищённые изображения не включаются.

Browser E2E: login/2FA, права, редактирование/409, upload bad MIME/size, preview, publish, audit, rollback; затем отдельный Android-тест видимости замены. Полнота форм проверяется матрицей, не только скриншотом главной страницы.
