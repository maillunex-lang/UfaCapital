# Проверки и доказательства

## Уровни

Unit/domain: pure Go деньги/рецепт/спрос/AI scoring, границы и инварианты. DB integration: PostgreSQL18 с реальными миграциями/транзакциями. API: сервер+PG и разные роли. Godot: parser/import, integration scenes, UI+HTTP, Android install/run. Admin: production build и Playwright. System: два настоящих человека+два ИИ, offline/restart/VPS/backup.

## Критические случаи

1. Два потока покупают последнюю партию, только допустимый объём; balances/ledger/inventory сходятся.
2. Повтор ключа и тела возвращает прежнюю операцию; другое тело с тем же ключом=409. Timeout после commit не создаёт второй trade.
3. Ноль/минус/переполнение/max int64, нечужое владение, неактивный рецепт/сессия/роль.
4. Production input/output/payroll атомарны, нет выпуска при нехватке/полном складе, повтор tick безопасен.
5. Cancel vs fill, delivery повтор/порча, контракт после expiry, освобождение только оставшегося резерва.
6. Спрос не превышает budget/need/stock; grant и AI respawn ограничены, emission видима.
7. Все 14 возможностей ИИ и 6 профилей, шок цены, память после рестарта, убыток/смена/банкротство.
8. VIP expiry и отсутствие экономического эффекта; admin grant только разрешённой роли/своей маркированной компании, audit/ledger.
9. Asset completeness, invalid file, publish/hash mismatch/cache/rollback, Android реально показывает замену.
10. Snapshot/event gap, повтор outbox, рестарт каждой фазы, recovery без повторных процентов/зарплат.

## Производительность и баланс

До заявления ёмкости: профиль Go/SQL и Godot; synthetic100concurrent как начальная цель альфы, измерять p50/p95/p99/ошибки, tick lag и CPU агентов. Стартовые SLO-кандидаты: API p95<500 мс без Android-сети, tick завершается до следующего периода, без финансовых аномалий; не выдавать за выполненные. На Android фиксировать эталонный аппарат, OS, память и frame times, не только среднийFPS. Баланс проверять fixed seed и человеческими сессиями: отсутствие идеального бесконечного арбитража, прибыльные разные роли, объяснимые убытки.

## Формат результата

task ID, base/result SHA, версии, среда, команда, exit code, assertions, ссылки на CI/artifacts, ручные шаги и наблюдения, отсутствующие зависимости. Доказательства кода→тест; устройства→install/run evidence; VPS→HTTPS/migration/backup/restart evidence. DONE только после всех обязательных проверок карточки. REVIEW — готова правка, требуется доступная проверка/ревью; BLOCKED — обязательная проверка недоступна. Документационные этапы проверяются статически и не означают пройденные игровые тесты.

Постоянные отчёты и минимальные метаданные хранятся в roadmap/evidence; большие логи/APK/видео — GitHub artifacts/release storage с retention и хешем. При истечении артефакта не выдумывать, что он доступен. В приватных доказательствах не публиковать пароль/токен/IP-админдоступ.
