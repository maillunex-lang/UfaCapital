# ИИ-предприниматели: полный минимальный набор

Алгоритмические, не LLM. Один decision engine, persistent state, шесть профилей. В срезе активны минимум два разных агента; все шесть профилей доступны настройкой и испытываются. Человек/ИИ используют общие доменные команды; системный внешний сектор обозначен отдельно.

## Состояние и цикл

Agent: company_id, profile, specialization, goal, risk/credit tolerance, min_cash, reserve_days, capacity_limit, decision_seed, previous_decision_id. Memory: EWMA публичных цен/объёма, прибыль направления, ошибки прогнозов, успешность поставщиков, время смены стратегии. Запись решения содержит observation window, candidate actions, score, selected action, result/reason. Непубличные данные конкурента недоступны наблюдателю.

Цикл раз в несколько интервалов с конфигурируемым лимитом: обновить память → оценить деньги/долги/товар → построить допустимые кандидаты → score→проверить risk/budget → обычная command → сохранить результат. Бюджет кандидатов≤20 на решение как исходный предел. Цель score=ожидаемый cashflow−штраф риска−стоимость замороженных средств; веса зависят от профиля. Доход не известен заранее, используются запаздывающие оценки и bounded exploration. Seed и очередность сохраняются для replay.

## Проверка 14 возможностей

| № | Возможность | Сценарий и доказательство |
|---:|---|---|
| 1 | Создать компанию | Из конечного AI startup fund, company+ledger grant once |
| 2 | Выбрать отрасль | Сравнить мельницу/пекарню/торговлю; saved score/reason |
| 3 | Покупать/продавать | Реальные заявки/сделки/остатки и публичная метка ИИ |
| 4 | Анализировать спрос/предложение | EWMA/видимые объёмы, изменение заказа после дефицита |
| 5 | Открыть предприятие | Обычная rent/open command с оплатой |
| 6 | Расширить выпуск | Expansion после окупаемости, ограничение бюджета |
| 7 | Конкурировать | Два агента/человек претендуют на один рынок без скрытой квоты |
| 8 | Выбирать решения | В логах есть несколько кандидатов и причина отказа |
| 9 | Реагировать на цену | Контролируемый шок меняет цену/объём/поставщика |
| 10 | Сотрудничать/контракт | Offer/accept обеспеченной партии и выполнение |
| 11 | Ошибаться/убыток/банкротство | Недостаточный спрос, обслуживание/долг, обычная ликвидация |
| 12 | Помнить результат | После рестарта оценки и история сохраняются |
| 13 | Изменять стратегию | Серия убытков/ошибок приводит к смене после cooldown |
| 14 | Специализироваться | Устойчивая предпочтительная отрасль, разные портфели профилей |

Профили: осторожный — больше ликвидности/обеспечения; агрессивный — больше расширения/риска; торговый — оборот/ценовые разрывы (в одном городе тоже возможны разные заявки/сроки, без гарантированного арбитража); производственный — загрузка линий; инвестиционный — окупаемость новых/расширенных активов, без обязательной долевой биржи; смешанный — диверсификация. Ни один профиль не обязан выполнять невыгодное действие ради демонстрации; тестовая ситуация создаёт условия для действия.

## Надёжность и наблюдение

Агенты могут терять деньги и банкротиться. Новый агент — новая компания с отдельной ограниченной выдачей, старые долги остаются. Нет бесконечного respawn. Админка видит профиль/память/расходы/последнее решение, может менять параметры с effective_at, pause/resume decision loop; обязательства и работа предприятия при паузе решений продолжаются.

Приёмка: минимум два агента плюс два реальных аккаунта; сопоставление правил/стоимости команд человека и ИИ; сценарии всех 14 возможностей,6 профилей, рестарт/повтор decision и лимит CPU. Экономический симулятор на общей Go-логике; тестовые часы/seed, никаких дорогих запросов к Codex/Claude/Grok в игровом runtime.
